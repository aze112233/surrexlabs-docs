710|# Voting & delegation
711|
712|Voting converts community preference into an executable mandate. The live governance system is the source of truth for eligibility and counting rules.
713|
714|## Before you vote
715|
716|- Read the final proposal, not only its title or discussion summary.
717|- Check the requested budget, milestones, owner, and reporting plan.
718|- Review disclosed conflicts and material risks.
719|- Confirm that you are using the official governance domain.
720|- Understand whether the vote is signaling, binding, onchain, or subject to a later execution step.
721|
722|## Delegation
723|
724|Delegation lets a holder assign voting power without transferring token ownership, when supported by the governance system. Choose a delegate based on public reasoning, participation, expertise, disclosure practices, and alignmentâ€”not promised rewards.
725|
726|Delegation should be revocable. Holders remain responsible for monitoring the delegate and the live rules.
727|
728|## Proposal impact
729|
730|Different decisions may justify different safeguards. Routine operating choices can use lighter processes; treasury transfers, governance changes, and security-sensitive actions should require stronger review and execution controls.
731|
732|## After a vote
733|
734|The result should be recorded with the final proposal text, vote totals, relevant thresholds, and next action. Where execution is separate, status should remain visible until completion.
735|

737|This documentation intentionally does not state a quorum, voting period, snapshot method, or token balance rule because those parameters have not been defined in this repository. Check the official DAO interface for current values.
738|{% endhint %}
